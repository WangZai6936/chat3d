# chat3d

通过对话生成和修改可编辑的工业三维场景，支持静态沙盘与通用关键帧/表达式动画。前端为 React、TypeScript、Three.js；Web 使用同源模型代理，另有 Tauri 桌面端源码。

## 内部团队共享

0.2.0 新增单团队账号、团队资产库和场景库。个人草稿留在本机，显式确认后才发布；团队版本不可变，复制不覆盖原件。部署需要 Node.js 24 与持久化 SQLite 目录。详见 [团队部署、账号与使用说明](docs/TEAM-SHARING.md)。

## Agent 依赖

连续建模使用 `@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai`，均固定为 `1.0.0`。项目直接使用 `Agent` 和 OpenAI-compatible 流式适配器；会话、草稿、建模工具与复核规则由 chat3d 管理，不依赖 1.0 已移出的实验性 AgentHarness。

此升级不自动接入 Pi Coding Agent 的 Codemode、MCP 登录或终端界面，也不代表整体任务 Token 减少 40%。这些是独立能力，需要按产品需求另行集成。

## 本地启动

使用 Node.js 22.19+（推荐 Node.js 24，与 Docker 镜像一致）。

```sh
npm ci
npm run dev
```

生产 Web 部署：

```sh
npm run build
npm start
```

不能仅把前端静态目录上传到不支持代理的服务器。自定义模型地址、生产域名及 Docker 部署见 [PROXY.md](PROXY.md)。不要将 API Key 放入仓库或前端构建变量。

## 使用流程

1. 配置真实模型地址、Key 和模型 ID（不提供离线模拟生成）；连续建模需要服务支持工具调用、图片和流式输出
2. 描述场景或上传参考图；已有选中对象用于指代，默认不限制整个场景的修改范围
3. 每轮对话内查看计划、工具执行、错误和结果；耗时与用量放在次要位置
4. 连续建模执行中可发送文字或图片补充要求；当前工具完成后跳过未执行的旧操作，将新要求送入下一轮模型上下文。消息标明等待、已接收或未送达；停止后未送达内容可恢复。单次生成兼容模式暂不支持运行中引导
5. 生成结果先展示为草稿。可以直接继续发送调整要求，无需先应用；连续草稿最终应用为一笔可撤销事务
6. 满意后应用，或放弃整条未应用草稿。属性面板可直接“应用当前草稿并编辑属性”；应用和后续手动修改分别可撤销。中断时保留成功阶段；后续失败不会丢掉此前预览
7. 未应用的预览与执行中的任务均属于各自会话。可切换或新建会话并继续建模；当前标签页最多同时执行 2 个会话，同一会话顺序执行。第 3 个请求会明确拒绝并保留输入，不自动排队调用模型
8. 动画可在视口播放、暂停、拖动时间和调整速度；详见 [ANIMATION.md](ANIMATION.md)

## 删除场景模型

- 在画布或“结构”中选中对象，点击工具栏垃圾桶“删除选中对象”，或按 Delete。Shift / Ctrl / ⌘ 点击可多选；“结构”中的组件名称或视口“选择整台设备”可选中整组。
- 删除模型会移除选中零件及其子节点，并清理相关连接、动画目标和已删除的跟随源。一次多选删除是一笔历史，可用撤销/重做完整恢复。
- 对话可真正删除场景对象，仍先预览、后应用。明确的“删除选中的对象”或唯一模型名称走本地命令；歧义或复合要求交给模型判断。输入文字、生成中和待确认预览时不会触发键盘删除。
- 只改变当前会话场景，保留独立资产库的原件、版本、文件和材质。其他会话的模型与历史不受影响。

## 框选与多选属性

- 工具栏“框选对象”默认关闭“穿透”，按选框内最近几何表面的 ID/depth 像素选择；仅投影包围盒相交不再足以选中。开启“穿透：开”才包含前方对象后面的几何，穿透也按实际三角面相交判断。
- 拖动方向不影响结果，部分相交即可命中；Shift / Ctrl / ⌘ 追加，Esc、指针取消或切换模式会取消当前拖动。切换会话会关闭框选和穿透。
- “框选零件”不扩展选择。“框选模型”在命中零件后包含该模型全部成员，包括隐藏和框外成员。货架真实孔洞中露出的后方零件仍是可见几何，可能命中；如只需前方零件，可缩小选框或从结构列表选择。
- 可见选择按当前绘图缓冲区分辨率进行无抗锯齿 ID 渲染，每次读回最多 1024 × 1024 像素。小于一个像素的细杆/边缘可能没有命中像素；透明面按实体选取，不模拟透明叠加和贴图 alpha。装饰地面、网格、选框轮廓不作为模型选择目标。它不是与显示图像抗锯齿完全一致的像素分割。
- 三维上下文丢失或读回报错时保留原选区并显示错误，不悄悄改成穿透。测试覆盖数学相交、模拟 ID/depth 读回及状态恢复；实际 WebGL 驱动仍需在可用浏览器检查：本地运行 `npm run dev` 后打开 `/e2e/rectangle-selection.html`，点击运行按钮。
- 画布属性面板对选中零件的移动、旋转、等比缩放和改色使用一笔手动属性事务，不再受 200 个独立零件限制，不扩大到未选中的同模型零件。数值/文档校验失败则整笔不应用；成功后一笔撤销/重做。此同步事务没有中途取消按钮，应用前可关闭面板，应用后可撤销。“更多属性与材质”的批量颜色、表面参数和已有材质替换也采用同样事务，保留原材质筛选。AI 的每批命令、新增节点及资源预算保持不变。
- 资产详情操作统一为“编辑资产 / 编辑信息 / 更新预览图 / 版本与备份”；移除“用于新场景”。场景画布资产架仍可引用固定版本资产。

## 检查原则

- 用户的明确业务要求优先于默认方案、旧助手假设和高亮选择
- 名称、分类等非视觉修改不要求截图；单组件外观可近景检查；结构和布局使用全景；动画使用动态样本
- 元数据变化不会使已完成的视觉检查失效；批量复制允许完成后统一检查
- 保留结构合法性、修改范围、网络安全及实际资源预算；批次容量不足应分批处理，不能擅自削减目标
- 自检是生成辅助，不是工程认证、物理仿真或人工验收

## 大场景与重复资产

- 场景编辑和项目 JSON 重开没有固定的总对象数门槛；GLB 导入不再按总部件数截断。保留每个部件及固定资产版本；提示明确要求完成全部数量与位置，不能把每批容量误当成只需完成前 16 个或顶层。
- `add_saved_assets` 每次最多 16 个实例，继续分批才能完成更多位置；同一批次的同版本资产只读取一次。每次成功后仍使用现有阶段草稿保存机制，失败整批不改。恢复时须根据当前实例和位置继续，尚未实现自动分配位置、后台队列或刷新后自动续跑。
- 继续保留每批 200 条命令 / 3,000 个新增节点、单组件构建/资产输入限制、网格和贴图预算、项目 JSON / GLB 20 MB 文件预算，以及任务时间/轮数/Token 预算。触及实际资源保护会明确失败或保留未完成草稿，不会静默删减用户数量。
- 项目 JSON 改用紧凑序列化。追加模型不反复复制已有节点，文档父引用校验改为线性遍历；视口对同几何、同外观复用资源，各节点仍可独立编辑。当前仍是逐节点 Mesh 绘制，未加入 GPU 实例化；浏览器内存、显卡和截图预算仍影响可用规模。
- 容量回归使用确定性 28 零件资产 × 400 实例（11,200 节点）和 10,017 部件 GLB，覆盖分批生成、完整数量核对、预览应用、撤销/重做、替换、保存重开、资源复用及失败回滚。不代表任意硬件的帧率或真实模型服务生成质量已经验收。

## 需求核对与恢复

- 连续建模工具 `check_requirements` 整理用户原文中的明确要求，优先按同名完整组件核对数量和世界坐标包围盒尺寸，没有匹配组件时可匹配组件内零件（如台面、金属腿）；米制尺寸容差为 2% 或 1 厘米取较大值
- 自然“长×宽×总高”按 X×Z×Y 核对：length/width/height 分别对应几何 width/depth/height；“宽×深×高”按 X×Z×Y。明确其他轴、旋转或混合约定时保守标为待核对，不能拿另一维度的数字充当符合
- 三维不可用时，当前响应中的有效数据编辑结束后直接返回未经视觉验收的阶段草稿；截图运行失败最多尝试一次，不再自动循环复核。可继续修改或手动保留，恢复三维后再验收。纯文本结束回复不再自动续问，已有修改保持未确认
- 配色部位、排布语义、造型真实度和工艺仍标为待核对；找不到组件名称不等于缺失。模型提取可能遗漏，清单不代表全部需求已覆盖
- 不符合或未核对项随预览显示，允许保留阶段草稿，不以新检查无限阻止提交
- 执行中发送的消息先保存在输入框上方队列，可显式选择引导或只提问。只提问不允许模型修改场景；未发送的后续任务须手动准备并发送，不会自动调用模型
- 失败或停止的指令可从聊天记录恢复；下载诊断仅含状态、错误分类、轮次、用量和耗时，不含聊天、场景、图片、原始错误响应或凭据

## 数据与交付边界

- 并行任务运行在当前浏览器标签页，切换项目不取消任务；关闭或刷新页面会中断，重新打开只恢复已保存阶段草稿并标明中断，不自动续费调用。停止仅取消当前会话的接收，服务方可能仍在处理并计费用量。
- 并行截图使用单独的离屏三维场景并串行占用检查渲染器，不借用正在查看的会话画面；不可用时退回服务端或软件几何检查，软件图不能验收材质、光影或动画。
- 会话、执行历史及草稿在当前浏览器的 IndexedDB 自动保存；顶部显示保存进度或异常，并非云同步或多人协作
- 底部“尚未导出备份”只指项目 JSON 下载状态，与会话自动保存分开；下载发起后仍需自行确认文件落盘
- 模型配置及 Key 存在浏览器 localStorage，当前不是企业凭据管理方案
- 项目 JSON 保留可编辑场景和动画；GLB 当前仅导出静态模型
- 下载项目文件用于长期备份。聊天和任务历史保存在本地会话中，不包含在项目 JSON 中
- 当前动画基于对象变换、显隐、跟随及受限表达式；不支持任意脚本、骨骼蒙皮、物理或生产工艺仿真
- 桌面端源码存在，不代表已完成各系统安装包发布与兼容性验收

## 0.2 工作台优化

- 明确且唯一目标的单项改色、带引号改名、米/厘米/毫米移动和 box 单零件宽高深编辑优先使用本地命令。不是离线模拟生成：不创建替代场景，不猜测歧义，仍经过范围、位置锁、动画保留与预览确认。含图片或复合指令进入真实模型。
- 新增有界 `profile` 凸轮廓挤出与 `lathe` 旋转剖面，供模型表达斜切壳体、肩腰轮廓、变径构件。与视口、尺寸包围盒和 GLB 导出共享实现；旧版应用可能无法打开包含新类型的项目。
- 模型可读取可编辑结构参考：连贯弯臂的操作人员、空腔设备、梁柱货架、带防撞与导航结构的AGV。它们不是自动替换用户任务的演示，也不等于特定厂家的真实产品。
- 业务路线工具以相对位移、速度、停留、返回路径和载物绑定编译为原有动画轨道，保留不相关轨道；不做物理碰撞或自动避障，延长总时长会影响整个循环周期。
- 项目菜单增加“工作台检查与备份”：运行状态、场景质量线索、全部会话项目与聊天文字迁移。未确认草稿单独导入副本，不覆盖原项目。备份不含参考图片、撤销栈、模型API配置与密钥，用户自己写入聊天的敏感内容仍在聊天文字中。
- 浏览器版更新：先结束生成、下载备份、刷新页面；回滚前保留新格式项目副本。桌面应用不会随网站发布自动升级，请从受信任的代码来源重新构建更新，不要下载来历不明安装包。

### 验收分层

1. 自动化：`npm test`、`npm run build`、`node tests/worker-proxy.mjs`。
2. 用户操作：创建→预览续改→确认→撤销→保存→重新打开，检查对象、尺寸、材质、动画和会话隔离。
3. 真实视觉：必须在可运行WebGL的浏览器检查全景与近景、人物比例、设备空腔及部件连接、物流路线与动画；CPU数据检查和离线渲染不能冒充浏览器三维验收。
4. 模型用量：分别记录本地明确编辑和真实模型生成，不能把0Token短路径推广为复杂建模成本承诺。

## 独立资产库与场景库

- 顶部“资产库”是独立管理页：新增资产名称与分类，进入空白资产编辑项目，生成/导入后先应用预览，再点击“保存资产”。不再要求先建一个场景并选择其中的零件。
- 已保存资产可打开为独立编辑项目；保存创建新版本，旧版本保留。并发版本冲突会拒绝覆盖。资产目前保存静态模型，含动画项目需保留为场景或导出项目。
- “场景库”独立列出场景项目，支持新增、打开和“保存场景”。已有普通会话保留并作为场景草稿展示，不删除旧数据。
- 场景中“引用资产”使用资产的固定版本。实例可以调整与撤销，不修改资产原件；资产升级不会静默替换场景中旧实例。
- 编辑草稿自动保存在当前浏览器，明确点击保存后标记入库；目前没有账号云同步。工作区备份保留资产/场景类型，导入的资产编辑项目不继承对原资产的版本写入关系。

## 执行可见性与紧凑收尾

- 公开说明和真实执行状态同时展示；没有模型说明时，仍显示当前工具步骤、等待/接收状态和最近完成的步骤。不会伪造内部思维过程。
- 运行中直接用“发送引导”“发送问题”“保存后续任务”按钮提交。引导等当前操作结束后接收；问题禁止编辑；后续任务仅记录，需用户主动发送。
- 相同版本、相同目标与参数的截图复用，不重复渲染来制造进展。场景改变后重新取图。
- review_model 支持 completion，把已读取真实图像后的复核与预览提交合并；仍执行原提交校验，不能绕过最新证据、动画检查或未验收项。
- 单体流程建议合并可顺序执行的工具调用。实际轮数、耗时与Token取决于模型和任务，未承诺固定轮数或同质量加速比例。

### 单体复核范围修正

托盘真实验证发现：唯一可见模型的完整组件图曾被当作局部图，导致提交时再要求全景。现在仅当取景目标覆盖原始场景的全部可见几何节点时，才同时作为全景证据；多对象或隔离诊断仍不能代替全景。空场景不再提供无目标的 detail_quality_standard 查询，固定标准仍在系统说明中，生成模型后恢复此工具。

验证样例为文字生成九脚网格托盘，不是用户原截图的同提示词对照：v85 实测 12 轮 / 12 工具 / 271660 已报告 Token，生成 57 零件并提交待确认，约 3 分多钟。发现上述两轮额外取图后修正，用真实守卫和模拟模型回放验证单对象可提交、多对象仍拒绝。没有把修正后的理论少两轮当作新的真实计时结果，也未声称全部材质质量通过。
