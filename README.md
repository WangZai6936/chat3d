# chat3d

通过对话生成和修改可编辑的工业三维场景，支持静态沙盘与通用关键帧/表达式动画。前端为 React、TypeScript、Three.js；Web 使用同源模型代理，另有 Tauri 桌面端源码。

## Agent 依赖

连续建模使用 `@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai`，均固定为 `1.0.0`。项目直接使用 `Agent` 和 OpenAI-compatible 流式适配器；会话、草稿、建模工具与复核规则由 chat3d 管理，不依赖 1.0 已移出的实验性 AgentHarness。

此升级不自动接入 Pi Coding Agent 的 Codemode、MCP 登录或终端界面，也不代表整体任务 Token 减少 40%。这些是独立能力，需要按产品需求另行集成。

## 本地启动

使用 Node.js 22.19+（推荐 Node.js 24，与 Docker 镜像一致）。

```sh
npm ci
npm run dev
```

生产 Web 部署：

```sh
npm run build
npm start
```

不能仅把前端静态目录上传到不支持代理的服务器。自定义模型地址、生产域名及 Docker 部署见 [PROXY.md](PROXY.md)。不要将 API Key 放入仓库或前端构建变量。

## 使用流程

1. 配置真实模型地址、Key 和模型 ID（不提供离线模拟生成）；连续建模需要服务支持工具调用、图片和流式输出
2. 描述场景或上传参考图；已有选中对象用于指代，默认不限制整个场景的修改范围
3. 每轮对话内查看计划、工具执行、错误和结果；耗时与用量放在次要位置
4. 连续建模执行中可发送文字或图片补充要求；当前工具完成后跳过未执行的旧操作，将新要求送入下一轮模型上下文。消息标明等待、已接收或未送达；停止后未送达内容可恢复。单次生成兼容模式暂不支持运行中引导
5. 生成结果先展示为草稿。可以直接继续发送调整要求，无需先应用；连续草稿最终应用为一笔可撤销事务
6. 满意后应用，或放弃整条未应用草稿。属性面板可直接“应用当前草稿并编辑属性”；应用和后续手动修改分别可撤销。中断时保留成功阶段；后续失败不会丢掉此前预览
7. 未应用的预览可随会话保留，允许切换到其他会话。正在执行时暂不允许切换，以免任务写入错误项目
8. 动画可在视口播放、暂停、拖动时间和调整速度；详见 [ANIMATION.md](ANIMATION.md)

## 检查原则

- 用户的明确业务要求优先于默认方案、旧助手假设和高亮选择
- 名称、分类等非视觉修改不要求截图；单组件外观可近景检查；结构和布局使用全景；动画使用动态样本
- 元数据变化不会使已完成的视觉检查失效；批量复制允许完成后统一检查
- 保留结构合法性、修改范围、网络安全及实际资源预算；批次容量不足应分批处理，不能擅自削减目标
- 自检是生成辅助，不是工程认证、物理仿真或人工验收

## 需求核对与恢复

- 连续建模工具 `check_requirements` 整理用户原文中的明确要求，优先按同名完整组件核对数量和世界坐标包围盒尺寸，没有匹配组件时可匹配组件内零件（如台面、金属腿）；米制尺寸容差为 2% 或 1 厘米取较大值
- 自然“长×宽×总高”按 X×Z×Y 核对：length/width/height 分别对应几何 width/depth/height；“宽×深×高”按 X×Z×Y。明确其他轴、旋转或混合约定时保守标为待核对，不能拿另一维度的数字充当符合
- 三维不可用时，当前响应中的有效数据编辑结束后直接返回未经视觉验收的阶段草稿；截图运行失败最多尝试一次，不再自动循环复核。可继续修改或手动保留，恢复三维后再验收。纯文本结束回复不再自动续问，已有修改保持未确认
- 配色部位、排布语义、造型真实度和工艺仍标为待核对；找不到组件名称不等于缺失。模型提取可能遗漏，清单不代表全部需求已覆盖
- 不符合或未核对项随预览显示，允许保留阶段草稿，不以新检查无限阻止提交
- 执行中可选择引导、只提问或记为后续任务。只提问不允许模型修改场景；后续任务仅保存，须手动准备并发送，不会自动调用模型
- 失败或停止的指令可从聊天记录恢复；下载诊断仅含状态、错误分类、轮次、用量和耗时，不含聊天、场景、图片、原始错误响应或凭据

## 数据与交付边界

- 会话、执行历史及草稿在当前浏览器的 IndexedDB 自动保存；顶部显示保存进度或异常，并非云同步或多人协作
- 底部“尚未导出备份”只指项目 JSON 下载状态，与会话自动保存分开；下载发起后仍需自行确认文件落盘
- 模型配置及 Key 存在浏览器 localStorage，当前不是企业凭据管理方案
- 项目 JSON 保留可编辑场景和动画；GLB 当前仅导出静态模型
- 下载项目文件用于长期备份。聊天和任务历史保存在本地会话中，不包含在项目 JSON 中
- 当前动画基于对象变换、显隐、跟随及受限表达式；不支持任意脚本、骨骼蒙皮、物理或生产工艺仿真
- 桌面端源码存在，不代表已完成各系统安装包发布与兼容性验收

```sh
npm test

```

## 0.2 工作台优化

- 明确且唯一目标的单项改色、带引号改名、米/厘米/毫米移动和 box 单零件宽高深编辑优先使用本地命令。不是离线模拟生成：不创建替代场景，不猜测歧义，仍经过范围、位置锁、动画保留与预览确认。含图片或复合指令进入真实模型。
- 新增有界 `profile` 凸轮廓挤出与 `lathe` 旋转剖面，供模型表达斜切壳体、肩腰轮廓、变径构件。与视口、尺寸包围盒和 GLB 导出共享实现；旧版应用可能无法打开包含新类型的项目。
- 模型可读取可编辑结构参考：连贯弯臂的操作人员、空腔设备、梁柱货架、带防撞与导航结构的AGV。它们不是自动替换用户任务的演示，也不等于特定厂家的真实产品。
- 业务路线工具以相对位移、速度、停留、返回路径和载物绑定编译为原有动画轨道，保留不相关轨道；不做物理碰撞或自动避障，延长总时长会影响整个循环周期。
- 项目菜单增加“工作台检查与备份”：运行状态、场景质量线索、全部会话项目与聊天文字迁移。未确认草稿单独导入副本，不覆盖原项目。备份不含参考图片、撤销栈、模型API配置与密钥，用户自己写入聊天的敏感内容仍在聊天文字中。
- 浏览器版更新：先结束生成、下载备份、刷新页面；回滚前保留新格式项目副本。桌面应用不会随网站发布自动升级，请从受信任的代码来源重新构建更新，不要下载来历不明安装包。

### 验收分层

1. 自动化：`npm test`、`npm run build`、`node tests/worker-proxy.mjs`。
2. 用户操作：创建→预览续改→确认→撤销→保存→重新打开，检查对象、尺寸、材质、动画和会话隔离。
3. 真实视觉：必须在可运行WebGL的浏览器检查全景与近景、人物比例、设备空腔及部件连接、物流路线与动画；CPU数据检查和离线渲染不能冒充浏览器三维验收。
4. 模型用量：分别记录本地明确编辑和真实模型生成，不能把0Token短路径推广为复杂建模成本承诺。
